## How this is launched

```
kedro run --pipeline materialize --params <prepared run parameters>
```

**`kedro run` is what runs the pipeline, and it runs inside a Spark session
`SparkSessionHook` builds from `conf/base/spark.yml`.** That command is the whole of the
launch, locally and on the cluster.

`spark-submit` does one thing: it PLACES that run on the cluster. It does not create the
session the pipeline computes in, and it is not where the session's configuration belongs —
a flag typed into a submit command is not part of the artifact whose hash was recorded, so
two runs of one artifact could compute differently with nothing to show for it. The exact
`spark-submit` line for a given cluster is that cluster's, and this project does not
invent one.
